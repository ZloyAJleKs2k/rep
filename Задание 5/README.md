# Модуль 5: Разработка проектной документации
### Информационная система «Бургер плюс»

## 1. Описание функционального назначения

Модуль реализует защищенный механизм входа в систему и управления пользователями для предприятия «Бургер плюс». 

Основные возможности системы:
* Проверка корректности введенных логина и пароля.
* Использование интерактивной капчи в виде пазла: перед входом пользователь должен правильно собрать изображение из фрагментов.
* Автоматическая блокировка аккаунта, если пользователь три раза подряд ошибся при вводе пароля или сборке пазла.
* Разделение прав доступа: обычный пользователь видит только рабочее пространство, а администратор получает доступ к панели управления.
* Управление пользователями: администратор может создавать новых сотрудников, редактировать их данные и снимать блокировки. При создании нового аккаунта система автоматически проверяет, не занят ли уже такой логин.
* Понятная обратная связь: система всегда сообщает пользователю об успехе, ошибке или блокировке через всплывающие окна с инструкциями.

## 2. Используемые операции и принимаемые данные

### Операция аутентификации
Принимает введенные пользователем логин и пароль, а также результат сборки капчи. Проверяет, существует ли такой пользователь, совпадают ли данные, правильно ли собран пазл и не заблокирован ли аккаунт. Возвращает статус входа и роль пользователя.

### Операция проверки капчи
Принимает текущее расположение фрагментов пазла на экране. Сравнивает его с правильным образцом. Возвращает результат: верно ли собрано изображение.

### Операция учета ошибок входа
Принимает данные пользователя, который пытается войти. Увеличивает счетчик неудачных попыток. Если счетчик достигает трех, возвращает команду на блокировку аккаунта.

### Операция блокировки и разблокировки
Принимает идентификатор пользователя и требуемое действие (заблокировать или разблокировать). Изменяет статус аккаунта в системе и при разблокировке сбрасывает счетчик ошибок до нуля.

### Операция создания нового пользователя
Принимает желаемый логин, пароль и назначаемую роль. Сначала проверяет, не существует ли уже пользователь с таким логином. Если логин свободен — создает запись и возвращает успех, если занят — возвращает ошибку.

### Операция редактирования данных пользователя
Принимает идентификатор пользователя, а также новые значения для логина, пароля, роли и статуса блокировки. Обновляет информацию в системе и возвращает результат операции.

### Операция отображения сообщений
Принимает заголовок окна, основной текст сообщения и его тип (успех, ошибка, предупреждение или информация). Показывает пользователю соответствующее всплывающее окно с нужной иконкой.
